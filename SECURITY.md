# Security Policy

## Scope

Macro Evidence does not maintain one organization-wide version-support matrix for every repository. Unless a repository publishes a more specific security policy, vulnerability reports are accepted for its current default branch and any currently deployed or publicly reachable surface it maintains.

## Reporting a vulnerability

**Do not disclose a suspected vulnerability in a public issue, discussion, or pull request.**

If the affected repository offers GitHub Private Vulnerability Reporting, you may use its **Report a vulnerability** workflow.

Otherwise, or if you prefer email, contact [security@macro-evidence.com](mailto:security@macro-evidence.com). Include, where applicable:

- the affected repository, component, page, or service;
- the affected version, commit, or environment if known;
- a concise description of the issue and its potential impact;
- reproduction steps or a proof of concept; and
- any relevant logs or screenshots with secrets and unrelated personal data removed.

Do not send credentials, private keys, access tokens, or other live secrets. If sensitive material is necessary to investigate the report, first use the email address above to coordinate an appropriate transfer method.

## Response and disclosure

Reports are reviewed on a best-effort basis. There is no guaranteed acknowledgement or remediation SLA at the current maintainer capacity.

Please allow a reasonable period for investigation and remediation before public disclosure. When useful, Macro Evidence will coordinate with the reporter on disclosure timing and may credit the reporter in the eventual advisory or fix unless anonymity is requested.
